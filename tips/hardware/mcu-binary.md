# 单片机与二进制：代码如何变成引脚上的高低电平

## 核心问题

`digitalWrite(13, HIGH)` 在 Arduino 里是一行代码，物理上发生了什么？

## 从代码到电平的链路
C 代码 → 编译器 → 汇编指令 → 机器码（二进制） → 烧录到 Flash
↓
CPU 取指令 → 解码 → 操作寄存器
↓
寄存器某一位 = 1 → 驱动电路 → 引脚输出 5V（HIGH）
寄存器某一位 = 0 → 驱动电路 → 引脚输出 0V（LOW）

## 二进制与硬件的映射

以 Arduino Uno（ATmega328P）为例：

- **PORTB 寄存器**：8 位，控制数字引脚 8-13
- 写 `PORTB = 0b00100000`（二进制）= `0x20`（十六进制）
- 第 5 位（从 0 开始数）= 1 → 引脚 13 输出 HIGH
- 其余位 = 0 → 引脚 8-12 输出 LOW

```c
// 这两行在物理上是等价的
digitalWrite(13, HIGH);
PORTB |= (1 << 5);  // 直接操作寄存器，更快
为什么工程师要懂这一层
表格
层级	你看到的	实际发生的	不懂的后果
应用层	digitalWrite(13, HIGH)	库函数封装	够用，但遇到时序问题抓瞎
寄存器层	`PORTB	= (1<<5)`	直接改硬件寄存器	能精确控制 ns 级时序
物理层	万用表测引脚 = 5V	MOSFET 导通，电流从 VCC 流向引脚	接错负载烧芯片
现场感悟
Arduino 默认 PWM 频率太低：analogWrite() 的 490Hz 控制 LED 没问题，控制激光器功率时响应太慢，必须改定时器寄存器提频到 10kHz 以上
引脚电流限制：Arduino 单个引脚最大 40mA，直接驱动继电器会烧，必须加三极管或光耦隔离
上拉/下拉电阻：按钮接数字输入时，如果不接上拉电阻，悬空引脚会随机跳变（浮空），程序读到一堆噪声
二进制位运算做状态打包：8 个开关量可以用 1 个字节（8 位）表示，串口通信时比发 8 个字符高效得多
与激光切割的关联
PLC 本质上也是单片机系统（只是封装更好）。理解"代码→寄存器→电平→继电器→电磁阀→气缸动作"这条完整链路，才能在现场调试时定位问题到底出在哪一环：是程序逻辑错了？还是 IO 模块坏了？还是电磁阀卡了？
